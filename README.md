# Columbia/Snake River Dam Dashboard

A Streamlit dashboard that brings three public data sources for the Columbia and
Snake River dams into one view, so fish passage can be looked at alongside the
river conditions and dam operations happening at the same time:

1. **Fish passage** — daily adult passage counts by species and dam.
2. **Water temperature** — river/forebay temperature at the same projects.
3. **Flow & power generation** — discharge, spill, and hydropower output.

The question the dashboard is meant to answer: how do fish runs line up in time
with water temperature and with how the dams are being operated?

## Data sources

| Source | What it provides | Scraper |
|---|---|---|
| [Columbia Basin Research DART](https://www.cbr.washington.edu/dart) | Adult fish passage counts; river environment incl. water temperature | `scrapers/dart_scraper.py` |
| [USACE monthly CSV archive](https://www.nwd.usace.army.mil/CRWM/Water-Control-Data/) | Hourly flow, spill, generation (MW), pool elevation — **federal projects only** | `scrapers/usace_scraper.py` |
| [USACE CWMS Data API](https://cwms-data.usace.army.mil/cwms-data/) | Hourly flow/elevation for **any** NWDP project, including the PUD dams | `scrapers/cwms_scraper.py` |
| [EIA-923 / EIA-930](https://www.eia.gov/electricity/data/eia923/) | Generation for the mid-Columbia PUD dams, which USACE does not publish | `scrapers/eia_scraper.py` |
| [Bonneville Power Administration](https://www.bpa.gov/energy-and-services/power/historical-streamflow-data) | System-wide generation mix (5-min); historical modified streamflow | `scrapers/bpa_scraper.py` |

All are public data published for programmatic use, and none require an API key.
Note the caveats in the `usace_scraper.py` docstring — that domain's robots.txt
disallows generic crawling, so keep request rates low and identify yourself in
the User-Agent.

### Why four sources for three measurements

Which source supplies flow and generation depends on who operates the dam:

- **Federal (USACE) dams** — one monthly CSV carries both flow and generation.
- **Mid-Columbia PUD dams** (Priest Rapids, Wanapum, Rock Island, Rocky Reach,
  Wells) — USACE publishes no file for them. Flow comes from the CWMS API;
  generation from EIA, because CWMS lists a `Power.Total` series for these
  projects but serves it empty.

Generation for the PUD dams forces a trade-off: **EIA-923** is exact per-dam but
monthly, while **EIA-930** is hourly but reported per balancing authority — and
only Wells maps 1:1 (Chelan PUD covers Rocky Reach *and* Rock Island; Grant PUD
covers Priest Rapids *and* Wanapum). EIA also reports *net* generation, after
station service, whereas the USACE `Gen` column is gross output; the two should
not be concatenated into one series without recording which is which.

### Two workarounds worth knowing about

**USACE TLS.** `www.nwd-wc.usace.army.mil` serves a valid DigiCert certificate
but omits the intermediate CA, so verification fails with "unable to get local
issuer certificate". `config/certs/usace-ca-bundle.pem` is the system trust
store plus that intermediate. Certificate verification stays on.

**Ragged USACE headers.** At BON, TDA, JDA, MCN, IHR and LMN the header row has
fewer fields than the data rows, so `pd.read_csv` raises. The data is fine.
Also note **row 2 of every USACE file is a units row**, not data.

## Layout

```
dam-dashboard/
├── scrapers/          # standalone fetchers, one per data source (CLI each)
│   ├── dart_scraper.py    # fish passage + water temperature
│   ├── usace_scraper.py   # federal dams: flow + generation
│   ├── cwms_scraper.py    # any NWDP project: hourly flow
│   ├── eia_scraper.py     # PUD dam generation
│   └── bpa_scraper.py     # system-wide generation mix; streamflow
├── config/            # dam lists, species codes, per-dam source map
│   ├── dams.py
│   ├── dam_availability.json   # generated by etl/validate_dams.py
│   └── certs/                  # USACE CA bundle (see below)
├── etl/               # normalize raw pulls into a common schema; load to DB
│   └── validate_dams.py        # one-off source-availability probe
├── data/raw/          # scraper output lands here, untouched
├── app.py             # Streamlit entry point
├── requirements.txt
└── README.md
```

## Dam coverage

`etl/validate_dams.py` probes every candidate dam against every source and
writes `config/dam_availability.json`. Current result — **13 of 19 dams have all
three measurements**:

| Dams | Flow | Generation | Temperature | Passage |
|---|---|---|---|---|
| BON, TDA, JDA, MCN, IHR, LGS, LMN, LWG | USACE CSV | USACE CSV | yes | yes |
| PRD, WAN, RIS, RRH, WEL | CWMS API | EIA-923 (monthly) | yes | yes |
| GCL, CHJ, LIB, ALF | CWMS API | — | yes | no ladder |
| DWR | CWMS API | — | tailwater (DWQI) | no ladder |
| HGH | CWMS API | — | none found | no ladder |

Temperature falls back through three tiers, and which one supplied the value is
recorded per dam: `Temp (WQM)` at the dam → `Temp (Scroll Case)` at the dam →
`Temp (WQM)` at the tailwater site. Each substitution sets a boolean
(`temperature_from_scroll_case`, `temperature_from_tailwater`) so a substituted
reading is never silently mixed with a forebay one. In practice scroll-case
exists only at BON and IHR, which already have a forebay monitor; the tailwater
tier is what actually rescues a dam, recovering Dworshak via DWQI.

Rerun the probe with:

```bash
python etl/validate_dams.py               # all candidates
python etl/validate_dams.py --skip-eia    # skip the ~20 MB EIA-923 download
```

## Running the scrapers

Each scraper is an independent CLI. Some examples:

```bash
# Adult Chinook and Steelhead passage at Bonneville, 2024
python scrapers/dart_scraper.py passage --projects BON --species Chinook Steelhead \
    --years 2024 --out data/raw/passage_bon_2024.csv

# Water temperature at Bonneville and McNary, 2023-2024
python scrapers/dart_scraper.py temperature --locations BON MCN --years 2023 2024 \
    --out data/raw/temps_2023_2024.csv

# Hourly flow and generation at Bonneville for all of 2024
python scrapers/usace_scraper.py fetch-year --site bon --year 2024 \
    --out data/raw/usace_bon_2024.csv

# Rolling 7-day BPA generation mix
python scrapers/bpa_scraper.py gen-live --out data/raw/bpa_live.csv

# Hourly flow at the mid-Columbia PUD dams (no USACE file exists for these)
python scrapers/cwms_scraper.py flow --sites PRD WAN RIS RRH WEL \
    --begin 2025-06-01 --end 2025-07-01 --out data/raw/midcol_flow.csv

# Monthly generation for those same dams
python scrapers/eia_scraper.py plant-monthly --year 2024 --dams PRD WAN RIS RRH WEL \
    --cache-dir data/raw/eia_cache --out data/raw/midcol_gen_2024.csv
```

Run any of them with `--help` for the full set of options.
